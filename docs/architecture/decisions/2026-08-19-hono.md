# Use Hono for the HTTP API

| Field | Value |
| --- | --- |
| Status | Accepted |
| Date | 2026-08-19 |
| Record type | Retrospective record of an implemented foundation decision |

## Context

Yetano Work needs a small TypeScript HTTP layer that composes middleware and module routes, uses
Web Standards request and response primitives, and can generate OpenAPI without starting a server or
connecting to PostgreSQL. Public API schemas must remain owned by the shared TypeBox contracts.

## Decision

Use Hono as the HTTP framework. Build the application through a side-effect-free `createApp`
factory, compose module route factories into the versioned API, describe public operations with
`hono-openapi`, and expose interactive reference documentation through Scalar. Keep the
`@hono/node-server` adapter at the runtime boundary.

Routes remain thin: they declare HTTP and OpenAPI behavior, resolve request-scoped services, and
translate known failures. Reusable application behavior does not depend on Hono types.

## Rationale

Hono provides the lightweight, TypeScript-friendly HTTP core the project needs without imposing a
larger application framework. Its Web Standards model keeps request handling explicit, while route
composition and OpenAPI integration fit the repository's contract-first API pipeline.

## Alternatives considered

- Express offers a mature ecosystem but would require more project-owned conventions and adapters
  for typed, contract-first route documentation.
- Fastify provides strong schema and plugin facilities, but its broader server and plugin model is
  more infrastructure than the current API foundation requires.

## Consequences

- HTTP code uses Hono routing, middleware, context, and error-handling conventions.
- The application/spec import path must remain free of server startup and database initialization.
- Domain and application services stay framework-independent so replacing the HTTP adapter does not
  require rewriting business behavior.
- Node.js deployment requires the Hono Node adapter, while API shapes remain portable TypeBox and
  OpenAPI artifacts.
- Contributors must understand Hono's middleware ordering and typed context model.
